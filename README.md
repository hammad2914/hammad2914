## `$ cat ./engineering-principles.md`

- **Design for change.** Business rules evolve; architecture should make changes predictable.
- **Keep abstractions useful.** Reuse should reduce complexity rather than hide it.
- **Measure performance.** Profile real bottlenecks before optimizing.
- **Protect data boundaries.** Permissions and tenant isolation are architectural concerns, not just UI checks.
- **Ship responsibly.** Tests, code reviews, validation, and observability matter beyond the happy path.
